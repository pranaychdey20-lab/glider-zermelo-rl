# BUILD SPEC (Track A)

Build, test and document a reproducible research project in this repo:
"Reinforcement-learning, energy-aware navigation of an underwater glider through synthetic ocean-current fields, benchmarked against straight-line and classical planning."

Problem: a glider moves at ~0.3 m/s and ocean currents are of similar speed, so heading straight at the target wastes energy. Given a current field, learn headings that reach a goal using little time and energy by exploiting the flow (a Zermelo navigation variant).

## Hard constraints
- CPU only (container: 4 cores, 15 GB). No hardware, no field data, no paid APIs. Network only for pip install.
- Python 3.10+: numpy, scipy, matplotlib, gymnasium, stable-baselines3, torch (CPU wheel), pytest, pyyaml, pandas, imageio. Use pathlib, no bash-only scripts.
- Config-driven (configs/default.yaml), deterministic given a seed, one command to train, one to evaluate.
- Git: commit after every stage; `git pull --rebase origin main` then `git -c push.negotiate=true push origin main`. Only touch non-literature paths (another session owns literature/). Never commit secrets or files > 50 MB.

## Model spec (deviate only with a note in docs/ASSUMPTIONS.md)
- Domain 50x50 km, 2D. Glider speed through water V=0.3 m/s constant. dt=600 s, max 400 steps. Start/goal sampled 20-35 km apart. Goal radius 1 km. Leaving domain = failure.
- Ground velocity = V*(cos h, sin h) + current(x,y,t). Use RK2 or sub-steps; show Euler drifts if you claim it.
- Currents from a stream function psi (u = dpsi/dy, v = -dpsi/dx, divergence-free): (1) random Gaussian eddies (3-6, radius 5-12 km, peak 0.1-0.5 m/s, random spin) + weak uniform drift; (2) a jet; (3) time-varying double gyre as HELD-OUT test field only. Each field from an integer seed. Verify sign and divergence numerically.
- Energy model (an ASSUMPTION, label it): e_step = (e_hotel + e_turn*|heading_change|/pi)*dt. Document units and the limitation (real glider energy is dominated by buoyancy pump and hotel load).
- Gymnasium env: action = continuous heading change in [-1,1] scaled to +/-30 deg per step. Observation (normalised, documented): goal vector relative to glider, heading sin/cos, local current, 5x5 patch of current samples, normalised time/energy used. Optional Gaussian observation noise on currents.
- Reward: -w_time*dt/T_scale - w_energy*e_step/E_scale + potential-based progress shaping k*(d_prev-d_now)/d0 + goal bonus - failure/timeout penalty. Log per-term magnitudes; prevent the stay-still loophole.

## Stages (in order; tests must pass before next stage)
0 Setup: venv, install, versions, skeleton src/glider_rl/{fields,dynamics,env,baselines,planner,train,evaluate,plots,animate,utils}.py, tests/, configs/, results/, docs/.
1 Fields, dynamics, straight-line baseline, tests, first animation. Tests: zero current + straight heading arrives at exactly d/V; uniform current gives vector-sum ground velocity; numerical divergence ~0 for every field; eddy spin sign matches convention; same seed same field; energy never negative; stepping deterministic.
2 Classical planner (grid graph, Dijkstra/A*, edge cost from ground speed and from energy model; time-optimal and energy-aware). Validate vs straight-line; report cases where it does not win. Animate straight-line vs planner.
3 Gym env + gymnasium check_env passes. Random policy and straight-line baseline inside env. PPO (SB3, 8 envs, CPU): quick 300k-step run first, confirm reward rises, then scale. TensorBoard + CSV logs.
4 Evaluation protocol (fix BEFORE looking at results): train maps seeds 0-9999, validation 10000-10099, test 100000-100199 (never used in training/tuning). 5 independent training seeds (3 if too slow, say so). Paired per-method metrics on identical test maps: success rate, arrival time, energy, path length, energy ratio vs straight-line. Mean+/-std over training seeds, bootstrap 95% CIs over maps. Save raw per-episode results to results/*.csv.
5 Experiments (priority order): 5a Pareto sweep (>=5 w_energy/w_time ratios x 3 seeds; plot time vs energy for RL, straight-line, planner). 5b Ablations: no current observation; no energy term; trained on one fixed map, tested on unseen maps. 5c Robustness: noisy current observations (3-4 levels); held-out double gyre.
6 Demos and figures, generated by scripts from saved raw results: 3-way animation (straight-line red, planner orange, RL green, streamlines, start/goal markers, live time/energy panel) as GIF < 10 MB and MP4; one failure-case animation; training curves with seed bands; results bar chart; Pareto plot. Provide `run_all.py` that reproduces everything without any model.
7 Handoff: docs/HANDOFF.md (what exists, how to run, results/summary.csv generated by script, deviations, known issues, unfinished work, honest DRAFT reading of numbers), docs/STATUS.md (checklist updated after every stage), docs/ASSUMPTIONS.md, docs/LEARN.md.

## Teaching mode

## Honesty rules
- Report only numbers measured by running code. If RL does not beat baselines, say so and diagnose. Never tune on test maps. Never report a single seed as the result. If a test fails, fix the cause, do not weaken the test. State in every summary what was not done.
- Type hints, docstrings, small functions, no hard-coded paths, no unused code. If a stage runs long, ship the simplest version that passes tests and note the gap in STATUS.md.
