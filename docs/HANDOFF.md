## What exists
- `src/glider_rl/`: current fields (eddies, jet, double gyre), RK2 glider dynamics, assumed energy model, Gymnasium env, straight-line / random / Dijkstra-planner baselines, PPO training, experiment launcher, evaluation + paired summary, plots, animations.
- `tests/`: 45 pytest tests (fields, dynamics, planner, env, summary statistics, training determinism). All pass.
- `configs/default.yaml`: every number used.
- `results/eval/*.csv`: one row per test episode for every method/run/condition (raw data behind every number).
- `results/summary.csv` (main test table), `results/summary_all.csv` (every condition): generated by `python run_all.py`.
- `results/figures/`: training curves, results bar charts, Pareto plot, robustness plot, GIF/MP4 demos (3-way, RL failure case, held-out gyre, stage 1-2 baselines).
- `results/trajectories/*.npz`: recorded demo trajectories (animations re-render without a model).
- `results/runs/<run>/`: config, per-episode training log, SB3 progress log for every run (models are git-ignored except `results/models/main_s0.zip`, 0.6 MB).
- Docs: `EVAL_PROTOCOL.md` (fixed before testing), `ASSUMPTIONS.md`, `LEARN.md` (teaching notes per stage), `STATUS.md` (build log).

## How to run
```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt && pip install -e . --no-deps
pytest -q
python run_all.py                    # tables + figures + GIFs from saved results (no model needed, ~50 s measured)
python run_all.py --evaluate         # re-run all test evaluations from trained models (needs results/runs/*/model.zip)
python run_all.py --full             # retrain everything (26 runs x 2M steps; estimated ~2-2.5 h on 4 cores from the measured run times) + evaluate + demos
python -m glider_rl.experiments --group long --parallel 5   # extra 6M-step runs
```

## Honest DRAFT reading of the numbers (test maps 100000-100199)
See docs/STATUS.md (stage 4 and 5 entries) for the full numbers with CIs.
- RL (PPO, 5 seeds, 2M steps) clearly beats the naive straight-line heading: success 80.4 +/- 2.7% vs 65.5%, and on the 120 maps every method solves it arrives earlier (24.9 vs 26.1 h).
- RL does NOT beat the classical planner: planner success 95%, planner time 23.5 h. The planner sees the whole current field (privileged, global information) while RL sees an 8 km x 8 km patch; this comparison therefore bounds what local sensing can achieve rather than being a like-for-like contest.
- Energy: under the assumed energy model no method saves significant energy over straight-line on the maps both solve (RL ratio 0.994 +/- 0.020, CI 0.975-1.013; planner 0.987). The model makes energy ~ hotel load x time + turning, so energy mostly tracks time; RL and planner save time but spend it back on turning.
- Pareto sweep: no meaningful time-energy trade-off appears. Removing the energy term (ratio 0) makes RL turn far more (57.5 vs ~45 kJ); any positive energy weight removes that, and ratios 0.25-16 are indistinguishable within seed noise. The planner dominates RL on both axes at every ratio.
- Robustness: RL success is unchanged with Gaussian noise up to 0.3 m/s on observed currents (80.4-81.0%), but its energy ratio rises from 0.99 to 1.64 because noisy inputs cause jittery heading changes. (Baselines read true currents, so they are flat by construction.)
- Held-out double gyre (never seen in training): all methods do well (straight 96%, planner 99.5-100%, RL 98.8 +/- 0.6%). RL has the lowest energy there (ratio 0.952 +/- 0.013 vs planner 0.97) but is slower than the planner (24.5 vs 23.1 h).

## Deviations from the spec
All listed in docs/ASSUMPTIONS.md. Main ones: goal-aligned observation frame (+ position and bearing), torch from PyPI (CUDA build running on CPU), 2M PPO steps per run, 3 seeds for Pareto/ablations.

## Known issues
- TensorBoard event files of `main_s*` are incomplete (a git autostash replaced them while training; episodes.csv/progress.csv were recovered in full from /proc). Training curves use episodes.csv.
- Planner path follower turns ~5x more than straight-line (turning energy 5-6 kJ vs 0.9 kJ per episode); a smoother tracking controller would likely improve planner energy.
- Energy model is an assumption; real glider energy (buoyancy pump per dive cycle) is not modelled; 2D only, no vertical dive profile.
